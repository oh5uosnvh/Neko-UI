# 纠正版 1.4.2-mg-2611142212

仍基于 pre22 定向分支，不合并后续架构。

## 备份界面与逻辑修正

- 移除新增兼容性说明及导入提示块。
- 导入显示全部四个选项，不根据文件中的可选节隐藏：分组和配置、仅追加导入分组和配置、路由规则、设置。
- 默认仅第一项勾选；导出同样仅默认勾选分组和配置。
- 保留原版格式编码与标签隔离。默认覆盖；同时勾选分组配置和追加时仅追加配置。
- 追加使用新的组/节点 ID，事务重映射所属分组、链节点、前置/落地节点、同时导入的规则出站；不清空已有组/节点或恢复标签元数据。无效引用、数据库失败不会留下半份追加。

## VMess 根因及实际验证

用户备份中的9个真实 VMess 均为 WS、非 TLS、auto、alterId0，但 path 已经在旧 pre22 导入时丢失。另一个存放在 VMessBean 的节点实际为 VLESS，不应误报为第10个 VMess。

新解析器修复不能从已经丢失的字段中重建原始 path。直接安装新包然后继续使用旧数据库/旧备份，仍会连接默认 `/` 并失败。不能再把合成 parser 测试通过当成用户节点连通性修复。

此次修正：
- modern ws-opts.Path/headers 优先于 legacy ws-path/ws-headers，优先级不依赖 YAML 键顺序。
- WS 不受未选择的 HTTP/H2/gRPC 参数覆盖；httpupgrade 不受 network 键顺序影响。
- 新增无私有数据的字段冲突和顺序回归。可选私有文件 smoke 测试实际运行 RawUpdater -> Bean -> Android outbound builder，输出仅留本地。

实际网络验证（无敏感节点值进入仓库）：
1. 用固定 core 源码构建 sing-box1.12.19-neko-1 Linux ARM64；使用相同服务器、UUID、Host等，仅切换空 path 与源 path。抽测3节点空路径全失败，源路径全返回 HTTP204。
2. 按 name+server/original-mapped-address+port+UUID+Host 唯一匹配原 YAML 和旧备份，9/9匹配。生成单独修复备份，保留2组94配置，不猜 path，不写死凭据到 APK，不自动在导入/启动时抓取订阅。
3. 保持旧备份中现有地址/hosts映射，9/9修复节点实际 HTTPS 请求均返回204。
4. 使用 Android 实际 RawUpdater 和 outbound builder 生成的9个出站配置，逐个实际请求均返回 HTTP204（约0.39–1.93秒；非应用测速数值，含连接与请求总耗时）。
5. 修复备份仍通过官方1.4.2及starifly1.4.2-rev-24实际读取代码读取2分组94配置。

部署时：用户需要在新版本中更新一次该订阅，或导入单独提供的路径修复备份。仅升级 APK 不会凭空恢复旧数据库已经丢失的 path。修复备份含用户节点凭据，严禁上传 GitHub、提交仓库或进入公共构建产物。
